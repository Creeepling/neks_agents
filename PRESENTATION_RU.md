# Платформа Neks Agents: Архитектура и Логика

Этот документ разделен на две части: **концептуальный обзор** для руководства и **техническую архитектуру** для команды разработки.

---

## Часть 1. Концепция продукта (Для Руководства)

### Что это такое?
Платформа представляет собой систему на базе искусственного интеллекта (ИИ) для автоматизации исследований и анализа недвижимости. В отличие от обычного "чат-бота", система использует концепцию **Мульти-агентных этапов**. Каждый этап — это отдельный цифровой специалист (аналитик, юрист, переговорщик), который имеет свою узкую специализацию и собирает строго определенные данные.

### Как это работает (Многоэтапный процесс)
Процесс анализа объекта недвижимости разбит на логические шаги:
1. **Выбор этапа:** Пользователь выбирает нужный этап анализа (например, "Инвестиционный анализ" или "Сбор базовой информации").
2. **Целевой диалог:** Открывается чат, где ИИ ведет диалог в роли профильного специалиста. ИИ задает наводящие вопросы и помогает пользователю структурировать мысли.
3. **Извлечение данных (Commit):** По завершении диалога, ИИ автоматически анализирует всю переписку, извлекает из нее ключевые факты (например, ожидаемую доходность, стоимость ремонта, наличие красных флагов) и аккуратно раскладывает их по полочкам в единую карточку объекта.
4. **Передача контекста:** Все собранные данные сохраняются. Следующий ИИ-агент (на следующем этапе) уже знает все, о чем вы договорились с предыдущим, и не задает повторяющихся вопросов.

### Ценность для бизнеса
- **Структуризация хаоса:** Пользователь просто общается естественным языком, а на выходе получается строгая таблица данных, готовая для отчетов.
- **Масштабируемость:** Мы можем легко добавлять новых "Агентов" (этапы) под любые бизнес-процессы компании.
- **Единое окно:** Интерфейс, данные и аналитика находятся в одной защищенной внутренней системе.

## Часть 2. Техническая архитектура (Для Разработчиков)

### Стек технологий
- **Backend:** Python 3.12, FastAPI, SQLAlchemy
- **Frontend:** Vanilla JavaScript, HTML5, CSS3 (работает без сборки)
- **AI / LLM:** Google Gemini API (с использованием библиотеки `instructor` для строгого извлечения JSON-структур).
- **База данных:** SQLite (для локальной разработки) / PostgreSQL (для продакшена в Google Cloud).
- **Инфраструктура:** Docker, Google Cloud Run, Cloud SQL.

### Структура базы данных (ORM)
Все данные изолированы по конкретному `User`.
1. **`users`** — Пользователи (содержит логин и bcrypt-хэш пароля).
2. **`properties`** — Объекты недвижимости.
   - Поле `data` (JSONB): Ключевое поле. Это гибкое хранилище, куда ИИ-модели "складывают" извлеченные структурированные данные после каждого этапа.
3. **`conversations`** — Диалоги по объектам.
   - У каждого диалога есть свой `current_step` (определяет, какой системный промпт ИИ и какую JSON-схему извлечения использовать).
4. **`messages`** — История сообщений внутри каждого диалога (хранится для контекста).

### Логика работы AI-Конвейера
1. **Валидация (`/validate`):** Перед стартом нового этапа бэкенд проверяет колонку `data` объекта. Если для этапа "Инвестиционный анализ" не хватает базовых данных (например, цены или площади), система выдает предупреждение.
2. **Чат (`/message`):** На каждое сообщение бэкенд подгружает историю диалога, добавляет системный промпт (роль агента) и отправляет запрос в Gemini.
3. **Извлечение (`/commit`):** Вызывается библиотека `instructor`. Она заставляет LLM прочитать всю историю чата и вернуть данные строго в формате Pydantic-модели (с проверкой типов данных: float, list, enum). 
4. **Слияние:** Полученный JSON объединяется с уже существующим JSON в колонке `data` объекта.

### Деплой и Безопасность
- **Авторизация:** Защита по JWT-токенам (JSON Web Token).
- **Хостинг:** Приложение упаковано в Docker. FastAPI настроен так, чтобы одновременно раздавать статический Frontend (UI) и обслуживать API. Это позволяет развернуть весь проект в Google Cloud Run как один монолитный сервис без проблем с CORS.
